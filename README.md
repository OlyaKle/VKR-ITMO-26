### Выводы по обзору

Изученные источники показывают, что оценка производительности работы отдела должна учитывать не только количество выполненных задач, но и сроки, качество результатов, взаимодействие сотрудников и особенности рабочих процессов.

Для разработки системы целесообразно использовать следующие подходы:

1. Использовать несколько показателей вместо оценки эффективности по одному критерию. В качестве основы можно рассмотреть SPACE Framework.
2. Использовать данные о выполнении задач для определения длительности операций, задержек и узких мест.
3. Использовать ИИ для интерпретации результатов анализа, выявления закономерностей и формирования рекомендаций.
4. Предоставлять результаты в понятной форме, позволяющей руководителю оценивать ситуацию и определять возможные направления улучшения работы отдела.

При этом существующие исследования не дают универсального решения, которое одновременно объединяет сбор рабочих показателей, анализ процессов и интеллектуальное формирование рекомендаций для руководителя отдела. Это определяет направление дальнейшей разработки.

## 3. Обзор и сравнение аналогов

### Прямые аналоги

**1. Atlassian Jira**

[Официальный сайт](https://www.atlassian.com/ru/software/jira)

Система управления задачами и проектами, позволяющая организовывать рабочие процессы, назначать исполнителей, отслеживать статусы задач и получать отчётность.

Основные возможности:
- управление задачами и проектами;
- настройка рабочих процессов (workflow);
- автоматизация операций;
- формирование отчётов по задачам.

Ограничения:
- сложная настройка рабочих процессов;
- большое количество параметров может перегружать интерфейс;
- для отдельных возможностей требуются дополнительные плагины;
- система автоматизирует существующие процессы, но не определяет самостоятельно, как повысить эффективность работы отдела.

Jira является наиболее близким аналогом по части управления задачами и рабочими процессами.

### Косвенные аналоги

**2. Microsoft Power BI**

[Официальный сайт](https://www.microsoft.com/ru-ru/power-platform/products/power-bi)

Платформа бизнес-аналитики для сбора, обработки и визуализации данных из различных источников.

Основные возможности:
- подключение к различным источникам данных;
- создание интерактивных отчётов и дашбордов;
- визуализация показателей;
- совместная работа с аналитическими отчётами.

Ограничения:
- для сложных аналитических задач требуются знания DAX и моделирования данных;
- при работе с большими наборами данных возможны замедления;
- расширенные возможности требуют платных лицензий.

Power BI является примером удобного представления аналитических результатов, но не предоставляет специализированного анализа производительности отдела с интеллектуальными рекомендациями в рамках рассматриваемой задачи.

**3. Tableau**

[Официальный сайт](https://www.tableau.com/)

Платформа бизнес-аналитики для исследования данных, построения визуализаций и создания интерактивных дашбордов.

Основные возможности:
- визуализация данных;
- объединение информации из разных источников;
- создание интерактивных дашбордов;
- поиск закономерностей и тенденций.

Ограничения:
- высокая стоимость лицензирования;
- некоторые функции требуют дополнительного обучения;
- возможности предварительной обработки данных ограничены по сравнению со специализированными инструментами;
- при работе с большими объёмами данных возможны проблемы производительности.

Tableau полезен как пример инструмента визуализации, однако не решает задачу комплексного анализа работы отдела с помощью ИИ-помощника.

### Выводы по сравнению

Проведённое сравнение показывает, что существующие решения хорошо справляются с отдельными задачами, но имеют ограничения относительно общей цели исследования.

Из Jira целесообразно использовать подход к организации и отслеживанию рабочих задач.

Из Power BI и Tableau — принципы подключения источников данных, визуализации показателей и построения аналитических отчётов.

В собственном решении планируется объединить эти возможности и дополнить их интеллектуальным анализом данных.

Основное отличие разрабатываемой системы заключается в наличии ИИ-помощника, который не только отображает показатели, но и интерпретирует результаты, помогает выявлять проблемы в рабочих процессах и формирует рекомендации по повышению эффективности работы отдела.

### Актуальность исследования

В современных организациях для управления работой отделов используются различные системы управления задачами, электронные таблицы и инструменты бизнес-аналитики. Однако информация о выполнении задач, сроках, загрузке сотрудников и результатах работы часто представлена в разных источниках. Для получения общей картины руководителю приходится самостоятельно собирать, обрабатывать и сопоставлять данные.

Существующие BI-системы, такие как Power BI и Tableau, позволяют визуализировать показатели, но требуют предварительной подготовки данных и настройки аналитических моделей. Системы управления проектами, такие как Jira, обеспечивают контроль выполнения задач, однако не всегда предоставляют достаточно возможностей для комплексной оценки эффективности работы отдела.

Дополнительные возможности открывает применение искусственного интеллекта. Исследования показывают, что ИИ может помогать сотрудникам при выполнении рабочих задач и повышать эффективность отдельных процессов. При этом для получения полезных результатов необходимы качественные данные и понимание особенностей работы организации.

Актуальность исследования также подтверждается распространением ИИ в российских компаниях. Согласно исследованию ИСИЭЗ НИУ ВШЭ, в 2024 году 57% организаций, использующих ИИ, отметили повышение качества или эффективности бизнес-процессов.

Таким образом, актуальной является разработка единой информационной системы, которая позволит собирать и анализировать данные о работе отдела, выявлять проблемные участки и использовать ИИ для интерпретации результатов и формирования рекомендаций.

### Цель исследования

Разработать информационную систему для автоматизации анализа эффективности работы отдела, обеспечивающую обработку рабочих данных, выявление проблем в процессах и формирование рекомендаций с помощью интеллектуального помощника.

### Задачи исследования

1. Изучить существующие подходы к оценке производительности сотрудников и анализу рабочих процессов.
2. Провести анализ существующих систем управления задачами и бизнес-аналитики, определить их преимущества и ограничения.
3. Определить основные показатели эффективности работы отдела и требования к исходным данным.
4. Разработать архитектуру информационной системы и определить способы получения и обработки данных из различных источников.
5. Реализовать механизмы расчёта показателей, анализа рабочих процессов и выявления проблемных участков.
6. Разработать ИИ-помощника для интерпретации результатов анализа и формирования рекомендаций.
7. Разработать интерфейс для представления аналитических результатов и взаимодействия с интеллектуальным помощником.
8. Провести тестирование системы и оценить корректность получаемых результатов.

### Датасеты и сервисы

Для разработки и проверки системы предполагается использовать собственные данные и открытые наборы данных.

**1. Собственный набор данных**

Основным источником информации будут данные о работе отдела, включающие:
- сведения о задачах и проектах;
- даты создания и завершения задач;
- статусы выполнения;
- назначенных исполнителей;
- сроки выполнения;
- историю изменения задач.

Для тестирования могут использоваться обезличенные данные или специально подготовленный набор тестовых записей.

**2. BPI Challenge 2017**

[Открытый набор данных Eindhoven University of Technology](https://research.tue.nl/en/datasets/bpi-challenge-2017/)

Содержит журнал событий процесса обработки кредитных заявок. Может использоваться для изучения и тестирования методов Process Mining, анализа последовательности операций, длительности процессов и выявления задержек.

Данный набор не предназначен для непосредственной оценки производительности сотрудников отдела, но подходит для проверки методов анализа процессов.

**3. Jira Cloud REST API**

[Официальная документация](https://developer.atlassian.com/cloud/jira/platform/rest/v3/api-group-issue-search/)

Может использоваться для получения информации о задачах, их статусах и других доступных атрибутах. Позволяет рассматривать интеграцию разрабатываемой системы с инструментами управления проектами.

**4. Yandex DataLens**

[Официальная документация](https://yandex.cloud/ru/docs/datalens/)

Может использоваться в качестве примера сервиса подключения источников данных и построения аналитических визуализаций. Также может применяться для сравнения подходов к представлению аналитических результатов.

**5. Сервис искусственного интеллекта**

Для реализации интеллектуального помощника предполагается использовать языковую модель через API. Она будет получать подготовленные результаты анализа и контекст задачи, интерпретировать показатели, объяснять обнаруженные проблемы и формировать рекомендации.

Конкретный поставщик модели и способ интеграции будут определены на этапе проектирования системы.
